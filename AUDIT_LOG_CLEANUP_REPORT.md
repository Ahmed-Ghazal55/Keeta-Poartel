## Cleanup design

The cleanup pass does not permanently hard-delete suspicious rows without a recoverable record.

Cleanup flow:

1. Read current `auditLogs`.
2. Classify each row through `AuditPolicy.classifyAuditRecord(...)`.
3. Keep the first valid allowlisted event per idempotency/signature.
4. Move phantom or duplicate rows to `auditLogsQuarantine`.
5. Preserve the original row in `originalRecord`.
6. Store runtime metadata for the cleanup execution.

## Quarantine model

Quarantined rows are stored in:

- `auditLogsQuarantine`

Stored fields include:

- `originalId`
- `cleanupRunId`
- `cleanupReasonCodes`
- `quarantinedAt`
- `source`
- `originalRecord`
