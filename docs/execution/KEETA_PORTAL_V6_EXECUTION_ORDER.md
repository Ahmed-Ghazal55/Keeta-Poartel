# KEETA Portal V6 — ترتيب العمل الصحيح لـ Codex

## التعديل الأساسي
تم تغيير نقطة البداية من المشروع القديم إلى المشروع الحالي:

- المشروع الحالي: `D:\keeta operations portal`
- المشروع القديم: `D:\KEETA OPR`

## الترتيب الصحيح
1. مراجعة المشروع الحالي كاملًا.
2. استخراج هيكل المشروع الحالي.
3. تحليل ملفات البيانات والمعادلات داخل الحالي.
4. إنشاء Audit وSchema Map.
5. بعد ذلك فقط مراجعة المشروع القديم.
6. مقارنة القديم بالجديد.
7. استخدام القديم كمرجع أو مصدر مكونات فقط عند الحاجة.
8. استخدام الملفات المرفقة كـ References إضافية.
9. تنفيذ التحويل على مراحل.
10. إنشاء تقارير التنفيذ والاختبارات.

## لماذا هذا الترتيب أفضل؟
لأن المشروع الحالي هو المصدر الذي سيتم التطوير عليه.  
لو بدأ Codex من القديم قد ينسخ كود غير مناسب أو يستبدل بنية المشروع الحالية.  
الترتيب الجديد يجعله يفهم الموجود أولًا، ثم يستفيد من القديم والاسكربتات بدون كسر المشروع.
